
LOG
===

Release notes, newest first. The version lives in VERSION as x.y.z: x is a
major version (0 until 1.0 is called), y a milestone, z the landings on main
since it. Each milestone and major has an annotated tag vx.y.0, so
`git log v0.9.0..v0.10.0` lists what a milestone covers. An entry is a
heading (version · date · name), a sentence on why it is a milestone, and a
few lines on what changed. Patches get a line only when one deserves it.

0.11.0 · 2026-11-11 · versioning
-------------------------------------------------------------------------------

The repo gets a version: VERSION, this log, the version on the banner's
shell line (".rc 0.11.0 · 42 ms · local"), `rcversion`, and a Version line
in `boot.sh --ensure`. The point is to see at a glance which .rc a machine
runs: setup/home had sat 265 commits behind main without anything saying so.

The backfill. Fifteen months of commits carried no version. Versions
0.1 to 0.10 were assigned after the fact, on 2026-11-11: each era starts at
the commit that introduced the structure it is named for, and its tag
carries that commit's date. The boundaries are judgement calls, not records.
Patches before 0.11 were never counted, so the backfill has only y.0
versions.

0.10.0 · 2026-10-25 · agents at work
-------------------------------------------------------------------------------

Coding agents become regular contributors, and the repo starts keeping the
rules they work by.

  - agents work in worktrees of their own and clean up after themselves
  - skills teach them how work is planned, tested and delivered here
  - hooks hold them to it, from planning to commit messages
  - lockmirror, a screen saver that leaves the screen as it was
  - a simple-first pass: plain ifs, no forks for constants at startup
  - tmux window jumplist and floating pickers; mini banner mode
  - hourly hr and rcstate sync agents under launchd


-------------------------------------------------------------------------------
0.9.0 · 2026-10-08 · modules and levels
-------------------------------------------------------------------------------

Today's architecture: one tool per directory, installed by its module.

  - bootstrap moves to .rcboot/<tool>, run from a module registry
  - --level=0..3 on Darwin and Linux, cutting packages by level
  - .zshrc, .tmux.conf, .vimrc and init.lua split into rc.d fragments,
    enabled per module
  - hostnames isg-<os>-<postfix>; a Debian 13 VM under lima
  - lldb, debuggers for Go, Python and Rust; rust-analyzer via lspmux
  - emacs line editing in every prompt; BANNER_MODE

0.8.0 · 2026-08-06 · it becomes .rc
-------------------------------------------------------------------------------

The repo takes its name and drops the last framework and the last IDE.

  - renamed from .dotfiles to .rc; oh-my-zsh gone the day before
  - one palette generates every theme (theme/generate.sh)
  - VS Code, Hyper and Docker Desktop removed; colima instead
  - tmux second layer, alerts, and omni's pane capture
  - the banner names the user, host, ssh peer and tmux servers
  - Hammerspoon window slots; startup caches for fzf, zoxide, plc
  - modern neovim, bat and delta installed on Linux
